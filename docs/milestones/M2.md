## 已落地（2026-11-09）

纵切片：C# 按钮 → `BridgeClient` → JNI → Java `DshNativeFacade` → Kotlin `RuntimeController` → DSHBox `sandbox-manager`（源码原样）→ PRoot → Debian 13 → Node 24 → 官方 DSH 0.2.1-rc.5。

| 组成 | 位置 |

## 真机结果（Honor PTP-AN10 / Android 17）

见 [COMPATIBILITY.md](../COMPATIBILITY.md)「M2 运行时」。摘要：导入 12 s、沙箱启动 7 ms、DSH READY 18.5–19.0 s；guest 内 `aarch64 / Debian 13.6 / Node v24.19.0 / dsh 0.2.1-rc.5`；后台 90 s 存活；停止与强杀后无孤儿进程。

## 与 DSHBox App 的差异 / 已知缺口

- 未移植 DSHBox `app` 模块里的启动前整理：`AptSourceProvisioner`（apt 源）、`GuestUserProvisioner`（guest passwd，终端里会显示 `I have no name!`）、`DpkgLedgerGuard`、`hardenDshboxAssets`、自有插件装配、Relay/开发者通道。DSH 本身不依赖它们即可 READY；终端（TASK-008）前需补 passwd。
- 运行环境包目前用 `adb push` 放到 App 专属外部目录再导入；正式版需 SAF 选择文件（TASK-007）或在线获取。
- `libproot.so` 不是 16 KB 页对齐（上游预编译件）：4 KB 页设备正常；16 KB 页设备可能无法运行，需跟进上游。
- DSHBox 上游现象：全新安装直接走离线导入时 `runtime-current/` 不存在，`swapRuntimeBody` 的 rename 失败后回退到 `copyRecursively`，会在悬空的 `/var/run` 符号链接处失败。我们在调用前创建该目录规避（不改上游）；建议向上游报告。
